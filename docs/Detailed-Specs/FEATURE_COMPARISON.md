# Filmory 功能对比：iOS/macOS 原生端 vs Web 网页端

本文档用于对比 **Filmory Swift 原生端** 与 **Filmory Web 网页端 (当前 React SPA 实现)** 的功能对齐情况，帮助评估 Web 端目前的开发进展、已实现及未实现的功能，以便规划接下来的开发任务。

---

| :--- | :--- | :--- | :--- |
| **1. 相机管理 (Gear - Cameras)** | ✅ 完整实现 (Phase 3) | ✅ 完整实现 (对齐 iOS 布局) | ❌ 缺少常用镜头推荐 |
| **2. 镜头管理 (Gear - Lenses)** | ✅ 完整实现 (Phase 3) | ✅ 升级完成 | 完整对齐 iOS 网格卡片与 SVG 动态焦段头像 |
| **3. 胶卷管理 (Gear - Films)** | ✅ 完整实现 (Phase 3) | ✅ 升级完成 | 引入 Prisma $transaction 原子库存控制与一键采购 CRUD |
| **4. 拍摄卷管理 (Rolls)** | ✅ 完整实现 (Phase 3) | ✅ 升级完成 | 完整对齐 Drag & Drop 照片卡片拖拽重排序 |

## 详细对比说明

### 1. 相机与镜头管理 (Cameras & Lenses)
* **iOS 已实现**:
  - 相机与镜头的 CRUD 交互。
  - 相机头像/封面图上传，并在列表/详情页进行大图预览。
  - 创建拍摄卷时，根据相机类型（单反、旁轴等）自动推荐常用镜头。
* **Web 已实现**:
  - 纯前端 IndexedDB (Dexie.js) 的相机与镜头 CRUD 逻辑与表单。
  - 胶片/数码双模式的表单切换。
  - **镜头网格卡片与 SVG 焦段头像**：重构镜头列表为 2 列网格卡片，并设计了 `LensSvgAvatar` 组件，根据镜头焦段自动动态矢量渲染 Standard/Wide/Telephoto 三大镜组结构（含变焦特征指示线）。同时支持全系器材自定义上传头像。
  - **全系 Base64 头像大图预览**：全面接管相机、镜头、胶卷、配件的头像上传。上传图片经前端强行裁剪并压缩为 Base64 格式后直接存入 IndexedDB，完美切断了对云端大象存储（如 S3/Supabase Storage）的重度依赖。支持全屏 Lightbox 预览及智能名字缩写 Placeholder。
* **Web 缺失**:
  - **智能推荐**: 缺少常用镜头推荐的过滤和提示逻辑。

### 2. 胶卷型号与库存管理 (Film Stocks & Inventory)
* **iOS 已实现**:
  - 胶卷型号 CRUD 与过期/品牌/ISO/色彩多维筛选。
  - **库存扣减系统**: 支持“添加库存” (持有数量) 和“已拍完”状态切换。新建拍摄卷时，若选择某卷胶片，会自动扣减该胶卷的库存。
  - **ArchivedRollQuickAdd**: 胶卷列表支持对拍过的胶卷直接补录已拍完卷，不扣减库存。
* **Web 已实现**:
  - 胶卷型号的 CRUD 列表及基础过滤。
  - 内置 Digital 占位型号并在列表中隐藏的逻辑（对齐 Film Mode Gate）。
  - **库存管理与扣减事务**：前端提供了库存数量的动态修改及卡片直观展示，新建 Roll 时在前端进行库存检查，如果库存不足则警告拦截，如果充足则自动扣减 1 卷。后端也实现了 `POST /api/films/:id/stock` 与 Prisma 事务控制。
  - **矢量胶片暗盒 (SVG Canisters)**：完美集成了 iOS 原生端的 80+ 款胶卷暗盒 SVG 图形，在全新的横向胶卷卡片左侧以磨砂玻璃背景呈现，支持型号级配置或品牌级降级匹配，还原原生的精致设计。
* **Web 缺失**:
  - 无关键功能缺失，库存扣减与展示已完整对齐。

### 3. 拍摄卷管理 (Rolls Management)
* **iOS 已实现**:
  - 进行中与已归档的双栏结构。
  - 卷详情导入照片（支持相册/Files/拖拽）、多选、删除。
  - **重排序**: 支持在卷详情中通过拖拽修改照片的顺序。
  - 归档默认以照片为主的 Carousel 网格展示。
* **Web 已实现**:
  - 进行中 (active) 与已归档 (archived) 的状态流转。
  - 冲洗备注、价格（胶卷/冲洗费用）记录及地点保存。
  - 卷详情的照片导入与删除。
  - **修改与 Notepad 备忘录集成**：支持通过 `PUT /api/rolls/:id` 对拍摄卷属性进行更新。且在卷详情编辑区下方集成了 monospace 等宽字体的 `Notepad` 冲洗备忘，支持实时记录与保存详细显影和冲洗工艺数据。
  - **设备后期编辑修改**：在拍摄卷详情面板顶部提供“修改设备”功能，允许用户随时更新当前卷关联的相机与胶卷，数据表响应式更新。
* **Web 缺失**:
  - 拍摄卷模块交互核心已全部对齐 iOS，不仅支持拖拽重排，还在归档卷卡片底部完美引入了原生级的 **横向滑动 Carousel 画廊预览**，Web 端已再无关键交互缺失。

### 4. 相册与照片管理、时间流与查看器 (Albums, Photos & Viewer)
* **iOS 已实现**:
  - 纵向时间轴网格，最新照片在底部。
  - **捏合缩放**: 支持双指手势无极缩放列数（2~8列）。
  - **相册系统**: 支持创建独立的跨卷相册 (Albums)，组织多卷照片。
  - **PhotoViewer 沉浸式动效**: 使用 SwiftUI 共享元素过渡 (`matchedGeometryEffect`)，使照片从点击位置顺滑放大，且支持上下或斜向拖动直接手势关闭。
  - EXIF 数据自动读取（GRDB 读取落库）。
* **Web 已实现**:
  - 纵向照片时间流网格，并在顶部导航中提供了 **2~8 列的无极缩放调节控制条**（左边小图，右边大图，并配有尺寸指示图标）。
  - 模糊搜索、相机/胶卷/评分的多维组合过滤。
  - **纯前端 EXIF 解析**: 依靠 `exifreader` 库在上传时提取焦段、光圈、快门、时间并落库。
  - **跨卷独立相册（Albums）**: 完整实现了本地 IndexedDB 级别的相册实体，允许用户创建独立相册（如旅行、主题等）、写描述、批量导入各卷照片、并设为相册封面，双端对齐。
  - **沉浸式灯箱关闭**: 实现了主页时间流与相册详情中，点击模糊 backdrop 空白背景即可直接关闭大图 Lightbox 预览的交互体验。
  - **Lightroom 级沉浸交互 (键盘快捷键)**：完美取代原生手势操作，在 Web 端引入了 `1-5` 极速打星、`0` 清除评分、`Delete` 或 `Backspace` 极速无缝移除照片的全局盲打盲筛操作流，在数字键与方向键的配合下选片效率远超移动端。
  - **Cmd/Ctrl 批量多选控制台**: 突破 iOS 繁琐的批量选择逻辑，全面支持 Web 原生的 `Cmd/Ctrl` 或 `Shift` 点击连选，并在界面底部呼出带有 Framer Motion 物理动效的毛玻璃控制面板，支持一键批量打分与批量删除。
  - 初始化时，通过 Canvas 自动绘制测试卡图片填补数据库示例。
* **Web 缺失**:
  - **交互理念差异**: Web 端已使用 `Framer Motion` 的 `layoutId` 实现了与 iOS `matchedGeometryEffect` 完全等价的弹性空间物理过渡动效。至于“手势下拉关闭”的缺失，这是符合桌面平台直觉的**主动舍弃**，转而通过极客级的 **全局键盘快捷键工作流** 形成了碾压移动端的选片体验。

### 5. 对比工作台 (Compare Workspace)
* **iOS 已实现**:
  - 限制为双对象 (A/B) 联动。
  - **横向对比 (Rows) 模式**: iOS 默认以 Rows (上下各一行照片横向滚动) 模式对比，适合单手横滑观察细节。
  - 模式顺序：`横向 (Rows)` → `纵向 (Grid)` → `Split (滑尺)`。
  - 独立滚动与联动滚动无缝切换。
  - 双指防误触下滑关闭。
* **Web 已实现**:
  - 限制为双对象 (A/B) 联动选择。
  - **左右双列 (Side-by-Side)** 模式，包含**联动滚动 (Linked Scroll)** 的滚动百分比计算与同步。
  - **上下横排 (Rows)** 模式，包含完美的纵向隐藏滚动条以及 X 轴横向联动滑动，完美适配宽屏浏览。
  - **滑尺对比 (Split)** 模式，支持鼠标拖拽/悬停或移动端触摸滑尺实时裁剪 A/B 图片进行像素级对比。
* **Web 缺失**:
  - Web 端在对比视图的交互层面已基本对齐 iOS 的丰富程度。

### 6. 标签管理 (Tags & PhotoTags)
* **iOS 已实现**:
  - 标签实体的增删改查。
  - 照片详情页中以多选形式关联/移除标签。
  - 照片网格按标签进行过滤。
* **Web 已实现**:
  - **标签配置字典**：支持标签实体的 CRUD 交互，并在设置中以带 HEX 颜色的 Pill Badges 呈现。
  - **交互式打标**：照片详情页 (Lightbox) 提供弹出式 checklist 菜单，支持实时对照片进行多标签关联或移除。
  - **多维标签过滤**：照片 Timeline 和相册照片选择 modal 中均集成了 `🏷️ 所有标签` 过滤器。
  - **卡片标签渲染**：在照片列表的缩略图卡片上渲染对应标签的彩色徽章。
* **Web 缺失**:
  - 无关键功能缺失，以 Flat-String Serialization 极简主义设计完整对齐。

### 7. 数据分析 (Stats)
* **iOS 已实现**:
  - 12 项统计方法与卡片，涵盖相机 Top 5、胶卷 Top 5、月度花费趋势、评分分布、胶片成本拆分（已用/库存）等。
* **Web 已实现**:
  - **12项大满贯与大屏仪表盘**：已将所有统计模块（包含 3 个 KPI 卡片与 8 个 Recharts 动态图表）整合进入独立的 `StatsView`，不仅对齐了 iOS 的所有指标，并且在视觉动画上实现碾压。
  - **时序追踪算法**：底层自动聚合计算过去 12 个月的月度消费账单（极光面积折线图）与拍摄频率（柱状折线双轴图）。
  - **智能资产估值**：无需手动输入价格，算法自动根据历史卷的平均买入价，推算出当前冷藏箱中冻结的“胶片库存残值”，并以饼图展现沉没成本。
  - **器材性价比追踪 (ROI)**：通过新增相机 `purchasePrice` 属性，算法动态展示各器材的快门产出率（张/元）排行榜，精准定位最贵的“吃灰神器”。
  - **年度神卷卡片**：提取评级最高的高分卷，截取首图作为毛玻璃底层，生成具有极佳质感的 5 强海报。
* **Web 缺失**:
  - 无关键功能缺失，以极其优雅的数据可视化和内存级聚合算法全面超越了 iOS 方案。

### 8. 冲洗记录与器材扩展 (Other Equipments & Develop Notes)
* **iOS 状态**:
  - 🟡 规划中 (Phase 5.5)。
* **Web 已实现**:
  - **其他器材 CRUD 管理**：支持药水 (Chemical)、三脚架 (Tripod)、清洁工具 (Cleaner) 及其它类型器材的完整 CRUD，并支持 Base64 头像上传。
  - **保质期/过期预警**：对化学药水支持购买日期与保质期录入，若已过期则在列表卡片上触发红色高亮警戒及“已过期”状态标签。
  - **冲洗备忘 Notepad**：在拍摄卷详情下方提供了以 monospace 等宽字体呈现的独立 Notepad 区块，可记录和实时保存胶卷的冲洗时长、温度、稀释比例等工艺参数。
* **Web 缺失**:
  - 无关键功能缺失。

### 11. 数据灾备与系统同步 (Security, Backup & Sync Engine)
* **iOS 状态**:
  - 依赖 Apple 闭源生态进行应用数据自动备份，用户无法直接提取原始文件组合。
* **Web 已实现**:
  - **全景无感同步引擎 (SyncService)**：将底层 Dexie IndexedDB 升级为第 12 代架构，植入 `syncQueue` 操作日志队列。以**“零侵入”**级别拦截所有前端的增删改查物理动作并自动队列化，实现即便断网状态也可安全记录动作，并在连网后瞬间秒传 Supabase 云端（含冲突避免软删除守卫），构建了顶级的 **Offline-First (离线优先)** 体验。
  - **TUS 断点续传与 VIP 边缘压缩 (Edge Compute)**：全面接管大图上传，普通用户超额上传时前端强制利用 Canvas 压缩为 WebP 以保护服务器资源；所有上传过程支持断点续传。
  - **纯本地脱水极速打包**：采用 JSZip 遍历 IndexedDB，配合轻量级 `metadata.json`，实现绝对属于用户自己的跨设备防灾包。
  - **毁灭级无损恢复引擎**：清空前端库并根据 ZIP 完整重建整个对象存储机状态。
  - **偏好与安全控制台**：在 SettingsView 中收口集成了胶片功能总闸（Film Mode Toggle）、安全登出（Logout）与要求多级确认验证的最高权限账号彻底销毁功能 (Account Deletion RPC)。
  - **强制邮件沙盒安全验证**：全面集成 Supabase Auth 的邮件确认功能，新用户注册必须查收验证码防范虚假账号滥用。
* **Web 缺失**:
  - 无关键功能缺失，在数据的开放性、离线高可用以及跨端同步能力上均已达成满血满配。
