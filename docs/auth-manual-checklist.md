# 认证前端闭环手动检查清单

本文档用于手动验收当前这轮新增/补强的认证前端代码，范围仅覆盖这次刚完成的认证 UI 与路由闭环，不等于真实生产邮件/生产 OAuth 已完成。

## 当前本地验证记录

2026-07-18 已完成本地 Supabase 验证：

- `supabase start` 成功启动本地 API、Studio 和 Mailpit。
- `supabase db reset` 成功从零库重放 migration chain 和 seed。
- 本地 Mailpit 已收到注册确认邮件。
- 本地 Mailpit 已收到密码重设邮件。
- 邮件链接包含 `http://127.0.0.1:5173/auth/callback`，并按场景带 `next=/auth/verified` 或 `next=/auth/reset-password`。

仍未完成：

- 生产 SMTP 真发信验证。
- 生产 OAuth provider 控制台配置验证。
- 线上域名下的 Redirect URL 验证。
- 完整人工点击邮件链接后的 session 刷新与重设密码页面提交验收。

## 范围

本轮应被手动检查的代码点：

- 登录 / 注册共页
- 未验证邮箱提示与重发验证邮件
- 找回密码页
- 重设密码页
- `/auth/callback` 回跳处理
- `/auth/check-email` 与 `/auth/verified` 状态页
- 密码强度规则与确认密码
- 登录页/私有路由守卫

## 环境分层

建议分两轮检查：

1. 无真实 Supabase 邮件链路
   - 只验证页面、路由、表单校验、前端错误态、回跳逻辑。
2. 有本地 Supabase + Mailpit
   - 继续验证真实验证邮件、重设密码邮件、链接回跳、session 刷新。

## 前置条件

### A. 纯前端检查

- 前端可正常启动。
- 当前浏览器使用干净会话，避免残留登录态影响结果。

### B. 本地 Supabase + Mailpit 检查

- 本地 Supabase 已启动。
- Mailpit 可访问。
- `Site URL`、`Redirect URLs`、密码重设 redirect、OAuth callback 已与前端路由一致。

## 检查项

### 1. 登录页基础入口

- [ ] 打开 `/login`，页面正常渲染。
- [ ] 页面默认显示“登录”态，不是“注册”态。
- [ ] 页面存在“立即注册”“忘记密码？”入口。
- [ ] 页面存在 Google / GitHub OAuth 按钮。
- [ ] 已登录状态下访问 `/login`，应自动跳到 `/dashboard`。

### 2. 注册切换与表单结构

- [ ] 点击“立即注册”后，页面切换到注册态。
- [ ] 注册态可看到：邮箱、密码、确认密码、密码规则提示。
- [ ] 注册态能看到“注册后需要先完成邮箱验证”的说明。
- [ ] 点击“返回登录”后，页面回到登录态，并清空刚才的密码类输入。

### 3. 密码规则

当前规则应为：至少 8 位，且包含大写字母、小写字母、数字。

- [ ] 输入纯小写或纯数字弱密码时，前端阻止提交。
- [ ] 输入少于 8 位时，前端阻止提交。
- [ ] 输入强密码后，规则提示应显示为满足状态。
- [ ] 注册态密码和确认密码不一致时，前端阻止提交。
- [ ] 重设密码页也执行同一套规则，不允许较弱密码绕过。

建议手动样例：

- 应失败：`weakpass`
- 应失败：`12345678`
- 应通过：`Strongpass1`

### 4. 登录失败态

- [ ] 输入错误邮箱/密码后，提示为用户文案，而不是直接暴露 Supabase 原始英文错误。
- [ ] 无效登录时，文案应接近“邮箱或密码不正确，请重新检查后再试。”
- [ ] 页面不应因为失败而跳出当前页或进入异常空白状态。

### 5. 未验证邮箱登录

- [ ] 使用未验证邮箱登录时，出现“该邮箱尚未完成验证”的提示。
- [ ] 同时出现“重新发送验证邮件”按钮。
- [ ] 点击“重新发送验证邮件”后，出现发送成功反馈。
- [ ] 若当前环境接了 Mailpit，应能在 Mailpit 中看到新邮件。

### 6. 注册成功后的验证状态页

- [ ] 注册成功后，应跳到 `/auth/check-email`。
- [ ] 状态页应显示“请检查邮箱”。
- [ ] 若注册时填写了邮箱，页面应显示目标邮箱。
- [ ] 文案应提示本地 Mailpit 或邮箱验证下一步，而不是停在无操作提示状态。

### 7. 找回密码页

- [ ] 从登录页点击“忘记密码？”可进入 `/auth/forgot-password`。
- [ ] 页面存在邮箱输入框和发送按钮。
- [ ] 提交后出现“重设密码邮件已发送”成功提示。
- [ ] 若当前环境接了 Mailpit，应能在 Mailpit 中看到重设密码邮件。

### 8. 重设密码页

- [ ] 直接访问 `/auth/reset-password` 且没有 recovery session 时，应看到“链接已失效或不可用”兜底页。
- [ ] 从真实密码重设邮件进入时，应能正常进入可提交的新密码页面。
- [ ] 新密码提交成功后，应提示“密码已更新，请使用新密码重新登录。”
- [ ] 成功后当前会话应被清理，用户回到登录入口重新登录。

### 9. Auth Callback 回跳

- [ ] 访问合法 callback 链接时，应能完成回跳，不停留在 loading。
- [ ] callback 失败时，应显示用户可读错误，不是裸英文 provider 错误。
- [ ] `error_description=Link expired` 这类场景，应看到“认证链接已过期”一类提示。
- [ ] callback 中 `next=/dashboard` 或其他站内路径时，应跳到对应页面。
- [ ] callback 中 `next=https://evil.example` 这类非站内路径时，应回退到 `/login`。

### 10. 私有路由守卫

- [ ] 未登录直接访问 `/dashboard`、`/rolls`、`/gear` 等私有页时，应被重定向到 `/login`。
- [ ] 登录成功后再访问私有页，应可正常进入。
- [ ] 退出登录后刷新私有页，应再次被送回 `/login`。

### 11. UI 与交互细节

- [ ] 密码输入框“显示 / 隐藏”切换正常。
- [ ] 移动端宽度下密码输入与按钮不溢出、不遮挡。
- [ ] 成功/失败提示样式一致，没有明显布局跳动。
- [ ] 注册、找回密码、重设密码、状态页的返回登录入口都可正常工作。
